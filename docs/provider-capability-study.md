# Provider Capability Study

Telchines can certify LLM provider integrations with a matrix-backed scratch-project harness. The harness covers `openai_compatible`, `local_command`, and `agent_runtime` providers without committing raw `.tel` artifacts.

Preview a matrix without calling providers:

```bash
python scripts/provider_capability_study.py --matrix docs/provider-matrices/openrouter.json --dry-run
```

Run an explicitly enabled live matrix:

```bash
TELCHINES_LIVE_OPENROUTER=1 \
OPENROUTER_API_KEY=... \
python scripts/provider_capability_study.py \
  --matrix docs/provider-matrices/openrouter.json \
  --include-live
```

Run the deterministic local-command matrix:

```bash
python scripts/provider_capability_study.py --matrix docs/provider-matrices/local_command.json
```

The OpenRouter compatibility entrypoint remains available:

```bash
python scripts/openrouter_capability_study.py --dry-run
python scripts/openrouter_capability_study.py
```

## Matrix Format

Matrices are JSON files with `schema_version: "0.1"`, a `name`, and a `providers` list. Provider entries map onto Telchines provider config plus a small `supports` block that selects scenarios.

Provider entries use env-var references for secrets and live gates:

```json
{
  "name": "openai",
  "kind": "openai_compatible",
  "capabilities": ["repair", "generation"],
  "base_url_env": "TELCHINES_OPENAI_BASE_URL",
  "base_url_default": "https://api.openai.com/v1",
  "model_env": "TELCHINES_OPENAI_MODEL",
  "api_key_env": "OPENAI_API_KEY",
  "enabled_env": "TELCHINES_LIVE_OPENAI",
  "live": true,
  "supports": {"repair": true, "generation": true, "shell": true}
}
```

Live providers are skipped unless `--include-live` is passed and their `enabled_env` is set to `1`. Missing env vars are reported as skip reasons such as `missing_env:OPENAI_API_KEY`.

## Scenarios

For each planned provider, the harness can run:

- offline and live `tel providers check`
- agent repair on a scratch missing-semicolon fixture
- SVA generation with validator feedback retries enabled
- cocotb generation with `py_compile` validation and retries enabled
- plain shell smoke with `/providers`, `/providers check`, `/transcript`, and `/exit`

Each run emits bounded stdout/stderr, elapsed time, parsed validation status, candidate ids, and attempt counts where available.

## Outputs

Reports are written under `.test-work/provider-capability-study/<matrix-name>/` unless `--scratch-root` is supplied:

- `<matrix>_provider_capability_summary.json`
- `<matrix>_provider_capability_summary.md`

Secret-looking environment values are redacted from the summary payload. Raw `.tel` run artifacts stay inside the ignored scratch directory.

## Presets

Checked-in presets live in `docs/provider-matrices/`:

- `openrouter.json`
- `openai.json`
- `ollama.json`
- `lmstudio.json`
- `llama_cpp.json`
- `vllm.json`
- `litellm.json`
- `local_command.json`
- `agent_runtime.json`

Hosted and local OpenAI-compatible servers are opt-in. The `local_command` and `agent_runtime` presets use a scratch fixture provider generated by the harness and are safe for deterministic smoke checks.
